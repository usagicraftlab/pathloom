2026-10-20。対象：Pathloom Desktop、ブラウザープレビュー、保存形式、生成処理、外部連携、配布・CI。
基準文書：`app-design-constitution.md`（提供文書を改変せず保存）。基準点：`c01aad6`。

## 適用範囲

文書は評価基準として適用した。文書だけを根拠に新機能や権限を追加していない。
今回の変更は、先に依頼された不整合修正、AI操作・状態表示、軽量化の範囲。
Output toolを同じ論理tool IDのObject間で共有する仕様は、明示指示どおり維持し、回帰確認した。
「全条に完全適合」「実機検証済み」とは判定していない。

## 10条の点検

| 条文 | 確認・今回の対応 | 残る課題・限界 |
| --- | --- | --- |
| 1 主作業に集中 | 常設チャット・不要なApply/Discardを除去。キャンバス上の指示カード、必要時だけ開くAI設定へ整理。形状を見ながら生成できる | 全画面の情報密度はmacOSの実画面でも確認が必要 |
| 2 意味と責任の一貫性 | 入力・保存・出力の設定検証を共通化。プリンタープロファイル、開発／配布のasset一覧を一元化。初期層高0.60mmを統一。疎なtool IDで大量の空行を作らない | 印刷数値に連動する複数graphは再計算状態を確認して出力する必要がある |
| 3 直接操作 | 空白クリック／✦で配置位置に指示。生成・再試行・中断をカード内で完結。既存Componentはコンテキストメニューから編集 | キーボード、トラックパッド、タッチでの操作体系全体の再設計は未実施 |
| 4 作業位置の安定 | 指示カードの画面外はみ出しを防止。閉じても同一セッションの未送信文を保持。正投影・軸方向・選択Object・表示対象・配置設定を保存復元。別モードから開いても保存層を維持 | 指示下書きの再起動後復元、path内の再生位置の復元は未対応 |
| 5 構造と動き | Surface/List/Booleanの接続口表現を実際の型へ修正。生成中のspinner、完了したnodeの短い出現動作。動きを減らす設定を尊重 | 既存node群の表示密度・階層は引き続き実利用で評価する |
| 6 表現と重要度 | 生成状態を文字でも区別。失敗理由・詳細・再試行を保持。出力失敗も消えるtoastだけでなく詳細欄へ残す。操作へ支援技術用の名前を付与 | アプリ全域の英語／日本語ラベルや数値表記は未統一。VoiceOverによる全操作確認は未実施 |
| 7 応答と最新結果 | Worker再利用・入力の重複排除・古い結果の棄却。ネイティブ処理の中断／25秒timeout／出力量制限。失敗時は前回の有効形状を薄く表示し、古い結果の出力を阻止。idle描画の常時監視を廃止。配置変更時のgeometry再生成を抑制 | 巨大STEPの解析や初回geometry作成にはなお計算時間が必要。実Macでの操作遅延は別途計測する |
| 8 必要な段階で制約 | 全出力で有限値・配置・build volume・Z下限・tool設定を検証。中間Curveに印刷条件を一括適用せず、import済みの非平面toolpathを維持。壊れたcodeは未接続でも構文検証 | **残る設計課題**：`cad-components.js`のprimitive中心Z=0、矩形配列のXY限定、数値範囲、`cad-pipeline.js`の手入力Curve点数制限など。計算量上限と表現制限を分けて再設計すべき。Stackの閉曲線・XY前提やBooleanの平面条件は演算契約として区別する |
| 9 判断と既存作業の保護 | 新AI Componentは未接続で追加。位置・接続を勝手に変更しない。最終生成失敗は元の定義へ戻す。中断／編集後の遅延応答を捨てる。共有Output toolを維持 | **優先課題**：生成エラーがあるprojectは現行Saveで拒否される。失敗中の作業も保存できるdraft形式、自動回復、終了時の未保存確認が必要。出力可能形式とは分けて設計する |
| 10 保存から実利用 | graph・形状・設定・視点の保存再開、G-code生成、AI成功／失敗／中断をブラウザーで通して確認。JS／Python／macOS RustのCIを追加 | macOS実アプリ、OSダイアログ、Keychain、実Codex、Rhino、実プリンターは未検証。ブラウザーのnative mockは代替にならない |

## 全体の構成と保守性

- 表示：素のJavaScript、Three.js、HTML/CSS。`app.js`がObject・preview・output、`cad-ui.js`がgraph操作を担う。両ファイルはまだ大きく、今後は責任別の分割が候補。
- 計算：CAD graphとQuickJS/WASMのCode ComponentをWorkerで処理。STEP B-repはPython/OCCT、Desktop呼び出し・ファイル・AI・プリンター接続はTauri/Rust。
- 実装済み：パラメトリックgraph、Library、DXF／STEP、配置・層preview、project保存、G-code、PrusaLink、Grasshopper連携。
- 旧HTTP bridge群は`legacy/`へ隔離。履歴資料は基準commitへのリンクに固定し、現行仕様と区別した。
- 未実装：汎用の曲面編集、STEP書き出し、衝突／gantry検証、CAD Python runtimeのapp内同梱。憲法からこれらの追加実装を推定していない。

## 次に行う順序

1. 失敗途中でも保存できるdraft／自動回復と終了時保護。既存project互換・出力guardを維持する。
2. 中間幾何の制約一覧を作り、演算上の必須条件、計算量上限、不要な表現制限を分類。開いた3D Curveや負Zを保存・再利用できる操作から順に拡張する。
3. 実Macでメニュー・ダイアログ・設定保存・起動再開・実AIの成功／中断／エラーを確認。
4. Rhino更新→形状再計算→保存再開→G-codeまで通す。PrusaLinkは接続／転送のみを先に確認し、印刷は利用者の明示操作で行う。
5. 英日表記・単位・キーボード／VoiceOver操作を全画面で揃える。巨大STEPで実測して次の性能改善箇所を決める。

検証の実行結果と性能測定は`maintenance-progress.md`を参照。
